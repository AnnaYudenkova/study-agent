# Учебный помощник

Консольный прототип ИИ-агента для учёта учебных заданий. Пользователь вводит команды, приложение сохраняет задания, показывает сроки и отмечает выполнение. На этапе ЛР2 LLM и сетевые запросы не используются.

## Технологический стек

- Язык и среда выполнения: Python 3.14, CPython (проверено на 3.14.2).
- Редактор: текстовый редактор; запуск и проверки из PowerShell. Специальная IDE не требуется.
- Окружение: стандартный модуль venv, менеджер зависимостей pip.
- Рабочие библиотеки: стандартная библиотека Python (dataclasses, datetime, shlex).
- Хранение: список объектов Task в памяти процесса, без файлов и базы данных.
- Отладчик: стандартный pdb.
- Линтер и форматтер: Ruff 0.17.2.

## Подготовка окружения и запуск

Установите Python 3.14 с pip и Git. В PowerShell:

```powershell
git clone https://github.com/AnnaYudenkova/study-agent.git
cd study-agent
git switch task2
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m study_agent
```

Активация окружения не нужна. requirements.txt описывает рабочие зависимости (внешних библиотек нет), requirements-dev.txt фиксирует версию Ruff. Оба файла и pyproject.toml хранятся в Git; .venv, кеши и .env исключены через .gitignore. Для самого приложения достаточно Python без установки Ruff.

## Команды

| Команда | Назначение |
| --- | --- |
| add "Предмет" "Описание" ГГГГ-ММ-ДД | Создать задание с номером и статусом «не выполнено» |
| list | Вывести все задания со статусами, отсортировав по сроку |
| due ГГГГ-ММ-ДД | Вывести невыполненные задания до даты включительно |
| done НОМЕР | Отметить задание выполненным |
| help | Показать справку |
| exit | Завершить приложение |

Аргументы с пробелами заключайте в прямые двойные кавычки. Дата должна существовать и иметь вид ГГГГ-ММ-ДД. Пустая строка пропускается. Неизвестная команда, незакрытые кавычки, неверные аргументы, пустой предмет или описание, неверная дата и отсутствующий номер выводят ошибку, после которой можно продолжить работу. Повторное выполнение done для уже выполненного задания также сообщает об ошибке.

Штатный выход: exit, конец потока ввода (в Windows Ctrl+Z и Enter) или Ctrl+C. Состояние сохраняется между командами одного запуска, но теряется после выхода. Номера выдаются последовательно с 1, срок задаётся с точностью до дня. Время сдачи и фильтр по предмету из плана ЛР1 пока не реализованы; для ЛР2 достаточно выбранных операций.

## Структура проекта

- study_agent/__main__.py — точка входа при python -m study_agent.
- study_agent/cli.py — ввод, разбор через shlex, проверка аргументов, вывод и цикл команд.
- study_agent/tasks.py — модель Task и операции TaskBook над общим состоянием.

Разделение позволяет использовать операции с заданиями независимо от консольного ввода и в дальнейшем подключить к ним инструменты агента.

## Проверки качества кода

```powershell
.venv/Scripts/ruff.exe check .
.venv/Scripts/ruff.exe format --check .
```

Для применения форматирования:

```powershell
.venv/Scripts/ruff.exe format .
```

Линтер проверяет ошибки Python, неиспользуемые имена, импорты и выбранные правила E, F, I, UP, B. Форматтер приводит отступы, пробелы и переносы к одному стилю.

## Отладка

```powershell
.venv/Scripts/python.exe -m pdb -m study_agent
```

В приглашении pdb поставьте точку останова командой b study_agent/tasks.py:24, затем c и в приложении введите add "Математика" "Задачи" 2026-11-10. После остановки: p subject, p title и p deadline показывают аргументы; n выполняет следующую строку; s заходит в вызов функции; c продолжает выполнение; q выходит из отладчика. Номер строки относится к созданию Task в методе add.

## Пример диалога 1

Добавление и выполнение задания в одном запуске:

```text
> add "Математический анализ" "Решить задачи 1–10" 2026-11-10
Добавлено задание № 1.
> list
1 | Математический анализ | Решить задачи 1–10 | 2026-11-10 | не выполнено
> done 1
Задание № 1 выполнено.
> list
1 | Математический анализ | Решить задачи 1–10 | 2026-11-10 | выполнено
> exit
До свидания!
```

## Пример диалога 2

Новый запуск; ошибочная дата не создаёт задания. Выполненные и более поздние задания не попадают в due:

```text
> add "Физика" "Отчёт" 2026-02-30
Ошибка: Укажите существующую дату в виде ГГГГ-ММ-ДД.
> add "Физика" "Отчёт" 2026-11-12
Добавлено задание № 1.
> add "История" "Доклад" 2026-11-08
Добавлено задание № 2.
> add "Программирование" "Практика" 2026-11-20
Добавлено задание № 3.
> done 2
Задание № 2 выполнено.
> due 2026-11-12
1 | Физика | Отчёт | 2026-11-12 | не выполнено
> done 99
Ошибка: Задание № 99 не найдено.
> exit
До свидания!
```

Для ручной проверки также введите help, неизвестную команду, add без аргументов, done abc и пустую строку. После каждой ошибки list должен показывать прежние данные. Перезапустите приложение: list должен сообщить «Заданий нет.». Даты в диалогах условные и не обозначают дедлайн лабораторной.
